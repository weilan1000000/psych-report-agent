# 报告检查技能

目标：按量化标准检查报告是否适合交付。

评分维度，总分 100：
- 忠实于测评结果，25 分：是否严格基于输入分数、等级和解释。
- 专业安全边界，20 分：是否避免诊断化、夸大化和编造。
- 维度覆盖完整，15 分：是否为每一个已测指标提供独立、可定位的解释，而不是每个模块只解释一个代表项。
- 个性化与具体性，15 分：是否结合当前用户场景，而不是泛泛而谈。
- 人性化表达，15 分：是否自然、温和、低 AI 味。
- 建议可执行性，10 分：建议是否具体、可操作。

## 输入层级与渲染一致性（硬检查）

- `level`、`percentile_band`、`interpretation`、`direction` 以评分服务输入为准；不得用统一分数阈值改写层级。
- 检查 `data_sketch` 的 `source_level` 是否与输入逐字一致，且可见 `level` 没有被加强或贬低。
- 如果报告输入只给原始分数、没有量表版本的层级或方向规则，不能给“优势区/常态区/潜力区”这类确定性标签。
- 报告渲染后还应检查：可见标题不能出现样本文件名、内部主题名或 prompt 信息；所有结构化章节应被显式呈现，或在渲染契约中标注为有意合并。
- 每个重点指标应有“简短专业界定 + 家长可理解的当前倾向”两层解释；专业不等于术语堆砌，不得使用伪科学表达。
- `detailed_indicator_analysis` 中每个已测指标都应以 `【指标名】` 作为独立块标题，逐项检查是否同时具备专业界定和通俗翻译。
- 单次分数不得归因成固定“性格”、人格或长期发展史。出现“性格里的……”“天生……所以……”等归因时，要求改为现阶段的行为策略、反应风格或互动倾向。
- 当建议不少于三条时，检查是否按“学习与日常、课外与探索、亲子互动与沟通”三类场景组织；未覆盖的类别应有数据依据说明。
- 当输入的 `classification_basis` 为 `class_rank_percentile` 时，检查是否沿用同班排名评级，并拒绝把原始得分当作 20/60/80 或 55/70 的评级阈值。
- 当输入的 `classification_basis` 为 `fixed_norm_20_80_raw_score` 时，检查报告和图表是否使用原始分与固定常模 P20/P80 来划分区域；若正文或图注把区域解释成班级排名、同伴百分位或百分制分数，视为重大问题。
- 在 `fixed_norm_20_80_raw_score` 模式下，检查主报告图表是否只显示箭头位置和区域，不在箭头旁直接标注具体原始分；完整数值应只出现在附录或结构化复核数据中。

硬性不合格：
- 出现医学诊断结论。
- 编造未提供的信息。
- 和输入分数方向明显矛盾。
- 给出危险或不合适建议。

输出检查结果时，应给出：
- pass: true/false
- total_score
- major_issues
- revision_instructions
